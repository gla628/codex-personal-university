# 学习排课

按用户正在使用或明确指定的语言交付内容；技能标识符保持不变。

把课程课时规划中的课次安排成实际可执行的学习顺序或日期表。复用已有课程表和课时明细，以最新学习进度为依据，不新建平行登记表。

## 输入与默认偏好

从已有对话和登记位置读取：已选择课程、课次主题及分钟、前置知识、最新学习状态、未完成部分、材料准备情况、可用日期与时间。已知信息不重复询问。

优先遵循用户给定的可用时间和节数。未给定时，可以提出“近期先排3次课，数量可调整”的暂定方案，并说明需要按实际时间校准。跨课程混排时优先不同课程各一次，而非同一门连续三次。需要连贯操作的实践课或用户主动选择时可以连续安排。这不是硬性每日配额，不意味着每天必须学完或固定上课时间。三次课按每次实际分钟计算，例如45＋45＋90为180分钟，不能一律算135分钟；休息与课后投入另外说明。

登记位置和写入授权以当前用户实际提供的信息为准；可参照同包中的 [学习记录绑定说明](../interactive-teaching/references/learning-record-binding.md)。未安装该配套技能时直接核对用户提供的配置，不猜表格地址或状态。

## 安排规则

1. 优先续完正在学习或暂停的课，尊重用户指定课程与优先级。未明确选择的候选课程保留候选身份，不自动排进正式长期计划。
2. 从剩余课次中按必要先修关系选取下一批；保持每门课自身顺序连贯，并在每天的不同课程间轮换，兼顾理论与实践负荷。不要为混排提前安排尚不具备基础的进阶课，也不要为了连续性默认把同一门课塞满一天。理解基础未检验时说明需要短检查，不把所有未知都变成必须重学的前置课程。
3. 默认先给近期可调整的安排。用户只确定三节但未确定日期时，可登记为首批待排期队列，日期与时间留空并写明；不能随意填今天、推断每日固定时段或把整门课排满日历。
4. 已知可用时间时检查总分钟是否容纳讲解、实践与合理休息。三节装不下就减少节数、缩小当日范围或调整日期，说明取舍，不压缩教学来凑配额。
5. 检查材料就绪程度。尚未备课的可列为“待备课/待排期”，不能称可立即开课；实际备课使用 lesson-preparation，实际教学使用 interactive-teaching。不因排课自动批量制作所有课件。
6. 发生暂停、延期或用户改变计划时，保留已经完成的信用，调整受影响的近期安排。日期已过不等于旷课或完成，不自动把所有后续日期整体顺延；用户有新约束时据此重新安排。

## 登记与进度

有明确排课登记授权时直接更新现有“课程表”；课程目录中必要的排课状态可以同步，但不改变选课身份、课次内容和历史学习记录。没有写入授权时先在对话中呈现安排。

按实时表头使用现有列。用课程编号＋课次序号核对主题、时长与明细；如有重复复习安排，再结合日期与用途判断唯一对象。写前读现状，只修改需要改变的行，保留用户手工安排；重复请求已满足时不重复追加。

课堂中的状态回写由 interactive-teaching 在实际学习事件发生时完成。排课时读取这些最新结果，不能根据“已排课”“已有PPT”或日期经过自行标记学习完成。用户直接报告某课已完成时，沿用同一授权绑定更新对应明细与安排，回读确认，并注明是用户自报；不伪造授课或考核证据。

写入后回读课程、课次、日期、状态等关键字段；只有验证成功才称已登记。未同步时明确区分本地已形成的安排和飞书实际状态，保留准确的待同步内容。

## 交付

简要给出近期安排、每次课时长、合计课内分钟、必要的备课或先修事项，以及日期仍待确定的部分。说明采用的节数只是基于当前可用时间的安排，不构成硬性每日配额。

本技能在用户当前请求或学习事件中工作；提醒、定时唤醒、跨对话发送及外部日历事件属于另外的动作，不能由排课默认启用。
