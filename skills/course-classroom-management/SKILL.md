# 课程教室管理

按用户正在使用或明确指定的语言交付内容；技能标识符保持不变。

规划对话负责课程安排和教室入口；每门课的独立教室负责该门课的备课、互动教学、答疑、练习、续学及进度登记。教室的生命周期覆盖整门课，不按课次重建。学习者回到规划对话时，从共享课程表读取实际进度，不依赖后台消息或自动记忆。

管理课程前，核对用户实际指定的课程目录、学习区及当前授权；配置要点见 [教室配置说明](references/classroom-context.md)。本包不附带个人表格地址或已有教室链接。

## 判断要打开还是创建

用户说“给某门课开教室”“去上这门课”时，核对课程编号、名称及选课身份。语境只能确定多门候选课时，只询问要进入哪一门；安装本技能、讨论机制或普通排课不等于立即创建所有教室。

先读课程总目录的“教室链接”。已有链接时，用官方 read_thread 核验目标身份和课程绑定；标题相似不足以证明同一课程。核验成功后复用并在用户要求进入时用 navigate_to_codex_page 打开。无需为打开对话发送新消息。

链接为空时用 list_threads 检查可能已有的教室，再读取候选对话核对课程编号和来源规划。存在唯一匹配就补登记链接；不重复创建。只有课程确实没有教室且当前用户请求覆盖创建时，才建立独立对话。

若登记指向已归档教室，按用户意图恢复原教室；无法访问或出现多个冲突绑定时，保留原入口，查明或提出精确缺项，不把读取失败当成不存在。

## 创建独立教室

使用当前环境提供的官方 create_thread，不能用临时子 Agent 代替侧栏独立教室。用户未指定项目时优先采用本地 projectless 对话，标题可用“【教室】课程名称”；模型和推理档位遵循用户选择或客户端默认，不硬编码。用户指定项目时先用 list_projects 选择真实项目，不随意继承其他工程仓库。若当前环境没有独立对话创建工具，给出课程交接文本和手动建教室的方法，明确未自动创建。

个人学习按照用户当前授权与实际环境约束执行；不要把示例作者的组织规则、账号权限或历史授权带给新用户。仍须核对真实课程身份和创建授权，不伪造已有教室或派发结果。

初始提示应是可独立执行的完整课程交接，不能只说“承接原对话”。至少包括：

- 本教室唯一课程编号、课程名、来源规划对话和用户要求的一门课一个教室约定。
- 用户已确认的实际用途、学习基础及偏好；未知处明确未知，不从课名推断能力。
- 该门课的完整逐课时规划，或可以实际访问的精确入口；当前课次、已完成内容、暂停位置及待巩固项。
- 已有材料的真实文件或链接；未备课明确写未备课。只有同主机可访问时才传递本地绝对路径，不把另一个主机的路径当成可用材料。
- 使用 lesson-preparation 为需要开始的一节课备课，使用 interactive-teaching 分段授课；不因建立教室批量备完整门课程。
- 用户实际选择的登记位置、课时明细和课程表入口、对应课程写入范围，以及用户已授权的状态、真实日期和必要笔记登记规则。按现行表头定位，不缓存行号。
- 当前明确动作：仅开教室时核对资料并给出开课入口，随后等待用户；用户同时要求上课时才准备并开始指定课次。提问后等待真实作答，不自行连续上完课程。
- 本教室只处理本门课；整门课程规划的重大修改和跨课程排课交回规划对话由用户决定。阶段性教学调整、补讲和续学在本教室完成。

不要在提示里要求普通进度、ACK 或每节课结果跨对话发送。用户本人可以直接回规划对话；规划对话需要进度时读共享表格或 read_thread。

## 放入学习区并登记

创建返回真实 threadId 后再操作分区。只有 clientThreadId 时保留同一次创建结果，通过官方列表或状态等待真实 ID，不拿临时 ID 写链接或重复创建。

用户已指定侧栏分区时，用 list_threads 核验该分区和精确教室身份，再 move_thread_to_sidebar_section；已经在目标分区就不重复移动。指定分区不存在时可用 create_sidebar_section 创建，再回读。重名冲突先查清，不猜选；未指定分区时保持现状。

按用户指定分区整理课程教室；“学习区”只是可选名称，不搬动规划对话或其他任务。分区回读需包含该 threadId 的成员项。仅创建成功、移动 success 或教室处于 running 状态不能证明侧栏入口已核验。

在课程总目录按课程编号定位唯一行，将真实 codex://threads/<threadId>?hostId=<hostId> 写入“教室链接”。保留用户现有工作簿结构，已有非空链接需先核验，不覆盖冲突入口。写后回读同一课程行；创建成功但写表失败时保留真实 threadId 并报告待补登记，下一次恢复补写，不再建教室。

创建过程报错且结果未知时，先核对列表和已返回 ID，再决定是否重试，避免重复教室。

## 复用与完成

同一门课的后续课次、练习、答疑、暂停恢复和结课复习始终使用原教室。需要交代新的教学动作时，只有当前用户授权覆盖向该精确课程教室发送该动作才使用 send_message_to_thread。普通打开原教室使用导航，不额外发送消息；本技能不自动授权向其他对话发送内容。

教室使用现有 interactive-teaching 规则随真实课堂事件回写本课程进度。开教室、生成课件、讲授结束、独立掌握分别判断，不凭对话创建或时间流逝标记已完成。规划对话按需读取最新表格，不启用后台轮询、定时唤醒或跨任务状态广播。

结课后保留教室、材料和链接供复习。仅在用户明确要求时归档；不因最后一课结束而自动删除或归档。

交付时说明创建或复用的课程、实际教室入口、学习区归位和表格登记结果，明确尚未备课或尚未开课。创建成功时按工具规范附 created-thread 指令；不要将技能静态校验描述为真实创建与授课全链路验证。
